# The Complete Internals of an LLM — From Raw Text to Predictions

Let me walk you through every piece of the machinery, explaining *why* each decision was made, *what problem it solves*, and *how the math actually flows*.

## 1. The Problem Statement — What Are We Even Solving?

Before a single weight is trained, we need to frame the problem precisely. An LLM is solving **autoregressive language modeling**: given a sequence of tokens $x_1, x_2, \ldots, x_{t-1}$, predict the probability distribution over the next token $x_t$.

Formally, we model the joint probability of a sequence by factoring it autoregressively:

$$P(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, \ldots, x_{t-1})$$

This is the **chain rule of probability** applied to language. The model's job is to learn $P(x_t \mid x_{<t})$ well. Everything — tokenization, embeddings, attention, FFN layers — is in service of computing this conditional probability accurately.

The training objective is to **minimize the cross-entropy loss** (i.e., maximize the log-likelihood of the training data):

$$\mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log P_\theta(x_t \mid x_{<t})$$

where $\theta$ are all the model parameters. Now let's understand how we actually compute this.

## 2. Tokenization — Turning Strings into Integer Sequences

### Why Not Characters or Words?

Characters give you a tiny vocabulary (~100 symbols) but very long sequences. Words give you short sequences but a vocabulary of hundreds of thousands with terrible handling of rare words. You need something in between.

**Byte Pair Encoding (BPE)** is the answer. Here's the core algorithm:

1. Start with individual characters as the vocabulary.
2. Count all adjacent pairs of symbols in your corpus.
3. Merge the most frequent pair into a new single symbol.
4. Repeat until the vocabulary reaches size $V$ (e.g. 50,257 for GPT-2, 100k+ for modern models).

So "unbelievable" might be encoded as `["un", "believ", "able"]` → `[42, 8837, 291]`.

The output of tokenization is a sequence of integers $[x_1, x_2, \ldots, x_T]$ where each $x_i \in \{0, 1, \ldots, V-1\}$. Nothing else. The model never sees strings — only these integer indices.

```python
import tiktoken  # OpenAI's tokenizer library

enc = tiktoken.get_encoding("cl100k_base")  # GPT-4's tokenizer
tokens = enc.encode("Hello, how are you?")
# → [9906, 11, 1268, 527, 499, 30]
# That's 6 tokens for a 19-character string
```

## 3. Token Embeddings — From Integers to Geometry

### The Problem with Integers

You can't feed the integer `42` into a neural network and expect it to understand that token 42 might be semantically related to token 891. Integers imply an ordering (42 < 891) that is completely meaningless for tokens.

The solution: **embed each token into a high-dimensional real vector** where *distance and direction encode meaning*.

An embedding table is simply a matrix $\mathbf{E} \in \mathbb{R}^{V \times d}$ where $V$ is vocab size and $d$ is embedding dimension (e.g. 768 for GPT-2, 4096 for LLaMA-7B). To get the embedding for token $x_i$:

$$\mathbf{e}_i = \mathbf{E}[x_i] \in \mathbb{R}^d$$

This is literally just an array lookup — you take row $x_i$ from the matrix. But during training, these rows get updated by backpropagation until the geometry of the embedding space reflects semantic relationships.

Why does this work? Because the loss function rewards predicting correct next tokens. The model learns that "king" and "queen" should be near each other because they appear in similar contexts. It discovers linear structure: $\vec{king} - \vec{man} + \vec{woman} \approx \vec{queen}$.

```python
import torch
import torch.nn as nn

vocab_size = 50257
d_model = 768

embedding = nn.Embedding(vocab_size, d_model)
# This creates a (50257, 768) matrix, randomly initialized

tokens = torch.tensor([9906, 11, 1268])  # "Hello , how"
x = embedding(tokens)  # shape: (3, 768)
# Each token is now a 768-dimensional vector
```

The embedding matrix has `vocab_size × d_model` parameters = ~38M for GPT-2. These are some of the most important parameters in the model.

## 4. Positional Encoding — Teaching the Model About Order

### The Attention Problem

Here's a critical insight: **the self-attention mechanism (which we'll cover next) is completely position-agnostic by default**. If you shuffle the tokens in your input, attention produces the exact same output (just shuffled the same way). The model has no idea that "dog bites man" ≠ "man bites dog".

We need to inject position information into the embeddings.

### Sinusoidal Positional Encoding (Original Transformer)

The original Transformer (Vaswani et al., 2017) used fixed sinusoidal encodings:

$$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i/d}}\right)$$
$$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i/d}}\right)$$

where $pos$ is the position (0, 1, 2, ...) and $i$ is the dimension index. The final input to the model is the element-wise sum:

$$\mathbf{h}_i = \mathbf{e}_i + PE_i$$

*Why sinusoids?* Because $PE_{pos+k}$ can be expressed as a linear function of $PE_{pos}$, which means the model can easily learn to attend to "token 5 positions ago" by learning a fixed linear transformation. Also, different frequencies encode different "scales" of position — low-frequency dimensions capture broad position (early vs late in sequence), high-frequency dimensions capture fine-grained position.

### Learned Positional Embeddings (GPT-style)

GPT models use a **learned** position embedding table $\mathbf{P} \in \mathbb{R}^{T_{max} \times d}$ where $T_{max}$ is the maximum context length. The input becomes:

$$\mathbf{h}_i = \mathbf{E}[x_i] + \mathbf{P}[i]$$

This is simpler — the model just learns what each position should "feel like" from data.

### RoPE — Rotary Position Embeddings (LLaMA, Modern Models)

Modern models like LLaMA use **RoPE**, which is more elegant. Instead of adding position to the embedding, we *rotate* the query and key vectors by an angle proportional to their position before computing attention scores.

For a 2D slice of the query vector at position $m$:

$$\mathbf{q}_m^{(2i:2i+2)} = \begin{pmatrix} \cos(m\theta_i) & -\sin(m\theta_i) \\ \sin(m\theta_i) & \cos(m\theta_i) \end{pmatrix} \mathbf{q}^{(2i:2i+2)}$$

where $\theta_i = 10000^{-2i/d}$. The key insight: when you compute $\mathbf{q}_m^\top \mathbf{k}_n$, the dot product depends only on the *relative position* $(m - n)$, not absolute positions. This gives the model natural relative position awareness and **better generalization to longer sequences**.

```python
def apply_rotary_emb(x, cos, sin):
    # x: (batch, seq_len, n_heads, head_dim)
    # Rotate pairs of dimensions
    x1, x2 = x[..., ::2], x[..., 1::2]  # even and odd dims
    rotated = torch.stack([-x2, x1], dim=-1).flatten(-2)
    return x * cos + rotated * sin
```

## 5. Self-Attention — The Core Mechanism

This is the heart of the transformer. Let me build up to it carefully.

### The Intuition

Imagine reading the sentence: "The animal didn't cross the street because **it** was too tired."

To understand what "it" refers to, you need to look back at "animal" with high attention, and look at "tired" to understand the reason. For each token, attention computes how much each other token is relevant to understanding *this* token, then aggregates information from all tokens weighted by relevance.

### Queries, Keys, and Values

Each token's embedding $\mathbf{h}_i \in \mathbb{R}^d$ gets projected into three vectors:

$$\mathbf{q}_i = \mathbf{h}_i \mathbf{W}_Q, \quad \mathbf{k}_i = \mathbf{h}_i \mathbf{W}_K, \quad \mathbf{v}_i = \mathbf{h}_i \mathbf{W}_V$$

where $\mathbf{W}_Q, \mathbf{W}_K, \mathbf{W}_V \in \mathbb{R}^{d \times d_k}$ are learned weight matrices, and $d_k = d / n_{heads}$ is the head dimension.

Think of it as a **database analogy**: the Query is what you're looking for, the Key is the index/label of each item, the Value is the actual content to retrieve. You compare your query against all keys to get relevance scores, then retrieve a weighted combination of values.

### The Attention Score Formula

For a sequence of $T$ tokens, we compute attention for all tokens simultaneously using matrix operations:

$$\mathbf{Q} = \mathbf{H}\mathbf{W}_Q, \quad \mathbf{K} = \mathbf{H}\mathbf{W}_K, \quad \mathbf{V} = \mathbf{H}\mathbf{W}_V$$

where $\mathbf{H} \in \mathbb{R}^{T \times d}$ is the matrix of all token representations.

The attention scores are:

$$\text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V}$$

Let's break this down step by step.

**Step 1: Compute raw scores** $\mathbf{Q}\mathbf{K}^\top \in \mathbb{R}^{T \times T}$. Entry $(i, j)$ is the dot product of query $i$ with key $j$: $\mathbf{q}_i \cdot \mathbf{k}_j$. High dot product = high relevance. This is just asking "how aligned is token $i$'s query with token $j$'s key?"

**Step 2: Scale by $\frac{1}{\sqrt{d_k}}$.** Why? When $d_k$ is large, dot products grow in magnitude proportionally to $d_k$ (because you're summing $d_k$ products of random values). Large dot products → extreme softmax outputs → near-zero gradients → training slows down. Dividing by $\sqrt{d_k}$ keeps the variance of the scores at 1 regardless of dimension size.

*Proof*: If $\mathbf{q}$ and $\mathbf{k}$ have components with mean 0 and variance 1, then $\mathbf{q} \cdot \mathbf{k} = \sum_{i=1}^{d_k} q_i k_i$ has variance $d_k$, so standard deviation $\sqrt{d_k}$. Dividing by $\sqrt{d_k}$ normalizes the standard deviation to 1.

**Step 3: Apply softmax row-wise.** Each row (corresponding to one query token) becomes a probability distribution over all key tokens. Entry $(i, j)$ tells you how much token $i$ should "attend to" token $j$.

**Step 4: Causal masking (decoder-only).** For autoregressive generation, token $i$ must NOT see tokens $j > i$. We add $-\infty$ to the score matrix entries where $j > i$ before softmax, making those weights exactly 0 after softmax.

$$\text{mask}_{ij} = \begin{cases} 0 & \text{if } j \leq i \\ -\infty & \text{if } j > i \end{cases}$$

**Step 5: Weighted sum of values.** $\text{softmax}(\cdots)\mathbf{V}$ takes a convex combination of all value vectors. Token $i$'s output is a mixture of all value vectors, weighted by how relevant each token is to token $i$.```python
import torch
import torch.nn as nn
import math

class SingleHeadAttention(nn.Module):
    def __init__(self, d_model, d_k):
        super().__init__()
        self.d_k = d_k
        self.W_Q = nn.Linear(d_model, d_k, bias=False)
        self.W_K = nn.Linear(d_model, d_k, bias=False)
        self.W_V = nn.Linear(d_model, d_k, bias=False)
        self.W_O = nn.Linear(d_k, d_model, bias=False)
    
    def forward(self, x):
        # x: (batch, seq_len, d_model)
        B, T, _ = x.shape
        
        Q = self.W_Q(x)  # (B, T, d_k)
        K = self.W_K(x)  # (B, T, d_k)
        V = self.W_V(x)  # (B, T, d_k)
        
        # Raw scores: (B, T, T)
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)
        
        # Causal mask: upper triangle → -inf
        mask = torch.triu(torch.ones(T, T, device=x.device), diagonal=1).bool()
        scores = scores.masked_fill(mask, float('-inf'))
        
        # Softmax over last dim (over key positions)
        weights = torch.softmax(scores, dim=-1)  # (B, T, T)
        
        # Weighted sum of values
        out = weights @ V  # (B, T, d_k)
        
        return self.W_O(out)  # (B, T, d_model)
```

## 6. Multi-Head Attention — Running Attention in Parallel

One head of attention captures one "type" of relationship between tokens. But language is rich — a token might need to simultaneously track syntactic roles, semantic similarity, coreference, and positional proximity. **Multi-head attention** runs $h$ attention operations in parallel, each with its own $\mathbf{W}_Q^{(i)}, \mathbf{W}_K^{(i)}, \mathbf{W}_V^{(i)}$, and concatenates the results:

$$\text{MultiHead}(\mathbf{H}) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\mathbf{W}_O$$

where $\text{head}_i = \text{Attention}(\mathbf{H}\mathbf{W}_Q^{(i)}, \mathbf{H}\mathbf{W}_K^{(i)}, \mathbf{H}\mathbf{W}_V^{(i)})$

In practice, $d_k = d / h$ so total parameters don't change. Each head operates on a $d_k$-dimensional subspace of the full $d$-dimensional embedding. One head might learn to track "which verb does this noun relate to?" while another learns "what pronoun does this refer to?"

The computational trick: instead of doing $h$ separate passes, you reshape and use batched matrix multiplication:

```python
class MultiHeadAttention(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.d_k = d_model // n_heads
        self.d_model = d_model
        
        # Single projection matrix for all heads (then split)
        self.W_QKV = nn.Linear(d_model, 3 * d_model, bias=False)
        self.W_O   = nn.Linear(d_model, d_model, bias=False)
    
    def forward(self, x):
        B, T, C = x.shape  # C = d_model
        
        # Project and split into Q, K, V for all heads at once
        QKV = self.W_QKV(x)             # (B, T, 3*C)
        Q, K, V = QKV.split(C, dim=-1)  # each (B, T, C)
        
        # Reshape to (B, n_heads, T, d_k) for batched attention
        def reshape(t):
            return t.view(B, T, self.n_heads, self.d_k).transpose(1, 2)
        
        Q, K, V = reshape(Q), reshape(K), reshape(V)
        # Now: (B, n_heads, T, d_k)
        
        # Scaled dot-product attention (all heads simultaneously)
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)  # (B, n_heads, T, T)
        
        mask = torch.triu(torch.ones(T, T, device=x.device), diagonal=1).bool()
        scores = scores.masked_fill(mask, float('-inf'))
        
        weights = torch.softmax(scores, dim=-1)  # (B, n_heads, T, T)
        out = weights @ V                          # (B, n_heads, T, d_k)
        
        # Concatenate heads: (B, T, d_model)
        out = out.transpose(1, 2).contiguous().view(B, T, C)
        
        return self.W_O(out)
```

The `W_O` projection at the end mixes information across heads — it lets the model learn which combinations of the different heads' outputs are most useful.

## 7. Layer Normalization — Keeping Activations Stable

Deep networks suffer from **internal covariate shift**: as the weights in earlier layers change during training, the distribution of inputs to later layers shifts constantly, making training unstable.

**Layer Norm** normalizes across the feature dimension (not the batch dimension like BatchNorm):

$$\text{LayerNorm}(\mathbf{x}) = \gamma \odot \frac{\mathbf{x} - \mu}{\sigma + \epsilon} + \beta$$

where:
- $\mu = \frac{1}{d}\sum_{j=1}^{d} x_j$ (mean across feature dimension)
- $\sigma^2 = \frac{1}{d}\sum_{j=1}^{d}(x_j - \mu)^2$ (variance across feature dimension)
- $\gamma, \beta \in \mathbb{R}^d$ are learned scale and bias parameters (initialized to 1 and 0)
- $\epsilon \approx 10^{-5}$ prevents division by zero

Why layer norm over batch norm? LayerNorm normalizes each sample independently — it doesn't need statistics across a batch. This is crucial for autoregressive generation where you process one token at a time.

**Pre-norm vs Post-norm**: The original Transformer used post-norm (LayerNorm after the residual addition). Modern models like GPT-2+ and LLaMA use **pre-norm** (LayerNorm before the sublayer). Pre-norm is more stable during training because the residual stream is always unnormalized, preventing the gradient from becoming too small.

```python
# Pre-norm transformer block (modern style)
def forward(self, x):
    # Attention sublayer with pre-norm
    x = x + self.attention(self.norm1(x))  # residual connection
    # FFN sublayer with pre-norm
    x = x + self.ffn(self.norm2(x))        # residual connection
    return x
```

## 8. The Residual Stream — Why Skip Connections Are Fundamental

Every transformer block adds its output to its input:

$$\mathbf{x}' = \mathbf{x} + \text{Sublayer}(\mathbf{x})$$

This looks simple but it's one of the most important design decisions. Why?

**Gradient flow**: During backpropagation, the gradient of the loss w.r.t. $\mathbf{x}$ is:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{x}} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}'}\left(1 + \frac{\partial \text{Sublayer}(\mathbf{x})}{\partial \mathbf{x}}\right)$$

The `1` term means gradients always have a direct path from output to input, bypassing any sublayer. Without this, in a 96-layer model, gradients would be multiplied by 96 Jacobians and would either vanish or explode.

**Information preservation**: The residual stream carries the original token information through the entire network. Each layer only needs to learn the *correction* (delta) to add, not the full representation. This makes each layer's job much easier.

**The "residual stream" view**: Think of a highway running from input to output. Attention and FFN layers are on-ramps that *add* information to this highway. The original token identity (from the embedding) is always present — it just gets incrementally refined.

## 9. Feed-Forward Network — The Memory Store

After attention, every token's representation passes through a position-wise feed-forward network:

$$\text{FFN}(\mathbf{x}) = \mathbf{W}_2 \cdot \text{GELU}(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1) + \mathbf{b}_2$$

where $\mathbf{W}_1 \in \mathbb{R}^{d \times 4d}$ and $\mathbf{W}_2 \in \mathbb{R}^{4d \times d}$. The hidden dimension is $4d$ (a standard choice from the original paper).

**GELU activation** (Gaussian Error Linear Unit):

$$\text{GELU}(x) = x \cdot \Phi(x) = x \cdot \frac{1}{2}\left[1 + \text{erf}\left(\frac{x}{\sqrt{2}}\right)\right]$$

where $\Phi$ is the standard normal CDF. Approximated as $\text{GELU}(x) \approx 0.5x\left(1 + \tanh\left[\sqrt{\frac{2}{\pi}}(x + 0.044715x^3)\right]\right)$.

Unlike ReLU (which hard-cuts negatives to 0), GELU stochastically gates inputs by their magnitude — small activations are probabilistically zeroed, large positive activations pass through. This has been empirically found to train better for language models.

**What does the FFN actually do?** Research (Geva et al., 2021) shows that FFN layers act as **key-value memories**. Each row of $\mathbf{W}_1$ is a "key pattern" and the corresponding column of $\mathbf{W}_2$ is a "value". When the input matches a key, the corresponding value gets added to the output. This is where the model stores factual knowledge — things like "Paris is the capital of France" live in FFN weights.

The attention mechanism figures out *which tokens matter for which other tokens*. The FFN, applied independently to each token position afterward, looks up and injects factual knowledge based on what that token's representation currently encodes.

```python
class FFN(nn.Module):
    def __init__(self, d_model):
        super().__init__()
        self.fc1 = nn.Linear(d_model, 4 * d_model)
        self.fc2 = nn.Linear(4 * d_model, d_model)
        self.gelu = nn.GELU()
    
    def forward(self, x):
        return self.fc2(self.gelu(self.fc1(x)))
        # x: (B, T, d) → (B, T, 4d) → (B, T, d)
```

**SwiGLU** (used in LLaMA): Modern models replace the standard FFN with a gated variant:

$$\text{SwiGLU}(\mathbf{x}) = \mathbf{W}_2 (\text{SiLU}(\mathbf{W}_1\mathbf{x}) \odot \mathbf{W}_3\mathbf{x})$$

where $\text{SiLU}(x) = x \cdot \sigma(x)$ (Swish activation) and $\odot$ is element-wise multiplication. This adds a gating mechanism that lets the network learn to *suppress* certain features via the gate vector $\mathbf{W}_3\mathbf{x}$.

## 10. Putting It All Together — The Full Transformer Block```python
class TransformerBlock(nn.Module):
    def __init__(self, d_model, n_heads):
        super().__init__()
        self.norm1 = nn.LayerNorm(d_model)
        self.norm2 = nn.LayerNorm(d_model)
        self.attention = MultiHeadAttention(d_model, n_heads)
        self.ffn = FFN(d_model)
    
    def forward(self, x):
        # Pre-norm + residual for attention
        x = x + self.attention(self.norm1(x))
        # Pre-norm + residual for FFN
        x = x + self.ffn(self.norm2(x))
        return x
```

## 11. The Language Modeling Head — From Vectors to Probabilities

After $N$ transformer blocks, each token position has a $d$-dimensional representation. To get next-token probabilities, we apply a final **linear layer** (the "LM head"):

$$\text{logits} = \mathbf{h}_T \mathbf{W}_{emb}^\top \in \mathbb{R}^V$$

Notice: $\mathbf{W}_{emb}^\top$ is the **transpose of the original embedding matrix**. This is called **weight tying** — the same matrix is used for both embedding and prediction. Empirically this works extremely well and halves the parameter count for this large matrix. Intuitively: if two tokens have similar embeddings, the model should predict them with similar probability in similar contexts.

Then softmax converts logits to a probability distribution:

$$P(x_{T+1} = v \mid x_{\leq T}) = \frac{\exp(\text{logits}_v)}{\sum_{v'} \exp(\text{logits}_{v'})}$$

But during training we don't apply softmax explicitly — we use `nn.CrossEntropyLoss` which combines `log_softmax + NLL loss` in a numerically stable way:

$$\mathcal{L}_{CE} = -\log\frac{\exp(\text{logits}_{x_{T+1}})}{\sum_{v'}\exp(\text{logits}_{v'})} = \log\sum_{v'}\exp(\text{logits}_{v'}) - \text{logits}_{x_{T+1}}$$

The second form (the **log-sum-exp** form) is computed via the identity $\log\sum_i \exp(a_i) = \max(a_i) + \log\sum_i \exp(a_i - \max(a_i))$, which prevents numerical overflow.

## 12. The Full Model — Assembling All Pieces

```python
class GPT(nn.Module):
    def __init__(self, vocab_size, d_model, n_heads, n_layers, max_seq_len):
        super().__init__()
        self.token_embedding = nn.Embedding(vocab_size, d_model)
        self.pos_embedding   = nn.Embedding(max_seq_len, d_model)
        
        self.blocks = nn.Sequential(*[
            TransformerBlock(d_model, n_heads) for _ in range(n_layers)
        ])
        
        self.norm_final = nn.LayerNorm(d_model)   # final LN before LM head
        self.lm_head    = nn.Linear(d_model, vocab_size, bias=False)
        
        # Weight tying: embedding and lm_head share the same matrix
        self.lm_head.weight = self.token_embedding.weight
    
    def forward(self, idx, targets=None):
        # idx: (B, T) integer token indices
        B, T = idx.shape
        
        tok_emb = self.token_embedding(idx)       # (B, T, d_model)
        pos_emb = self.pos_embedding(
            torch.arange(T, device=idx.device)    # (T,) → (T, d_model)
        )
        x = tok_emb + pos_emb                     # (B, T, d_model)
        
        x = self.blocks(x)                        # (B, T, d_model)
        x = self.norm_final(x)                    # (B, T, d_model)
        logits = self.lm_head(x)                  # (B, T, vocab_size)
        
        if targets is not None:
            # Compute cross-entropy loss over all positions
            loss = F.cross_entropy(
                logits.view(B*T, -1),   # (B*T, V)
                targets.view(B*T)       # (B*T,)
            )
            return logits, loss
        
        return logits

## 13. Training — Backpropagation and Optimization

### The Forward Pass Produces Loss

Given a batch of token sequences, the model produces logits for every position. We shift targets by one: input is `[t_1, t_2, ..., t_{T-1}]`, target is `[t_2, t_3, ..., t_T]`. At every position, the model predicts the next token.

### Backpropagation — How Gradients Flow

The loss $\mathcal{L}$ is a scalar. We compute $\frac{\partial \mathcal{L}}{\partial \theta}$ for every parameter $\theta$ via the **chain rule**. PyTorch's autograd engine builds a computation graph during the forward pass and traverses it in reverse during `.backward()`.

For a parameter $\mathbf{W}$ in layer $l$, the gradient flows as:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{W}} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(l+1)}} \cdot \frac{\partial \mathbf{x}^{(l+1)}}{\partial \mathbf{W}}$$

The residual connections ensure that at layer $l$:

$$\frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(l)}} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(l+1)}} + \frac{\partial \mathcal{L}}{\partial \mathbf{x}^{(l+1)}} \cdot \frac{\partial \text{Sublayer}^{(l)}(\mathbf{x}^{(l)})}{\partial \mathbf{x}^{(l)}}$$

The first term is a direct gradient copy — it always has magnitude at least as large as if there were no sublayer. This is why residuals solve the vanishing gradient problem.

### AdamW Optimizer

SGD with momentum works but LLMs use **AdamW**, which adapts the learning rate per parameter:

For each parameter $\theta$ at step $t$:

$$\mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1-\beta_1)\mathbf{g}_t \quad \text{(1st moment: momentum)}$$

$$\mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1-\beta_2)\mathbf{g}_t^2 \quad \text{(2nd moment: RMS of grad)}$$

$$\hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1-\beta_1^t}, \quad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1-\beta_2^t} \quad \text{(bias correction)}$$

$$\theta_t = \theta_{t-1} - \alpha \frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon} - \lambda\alpha\theta_{t-1}$$

The last term $-\lambda\alpha\theta_{t-1}$ is the **weight decay** (the "W" in AdamW). It decouples regularization from the adaptive learning rate — it directly penalizes large weights to prevent overfitting.

Standard hyperparameters: $\beta_1 = 0.9$, $\beta_2 = 0.95$, $\epsilon = 10^{-8}$, $\lambda = 0.1$.

The divisor $\sqrt{\hat{\mathbf{v}}_t} + \epsilon$ is an estimate of the RMS of gradients — parameters with consistently large gradients get a smaller effective learning rate, and vice versa. This **automatically adapts the step size per parameter**, which is crucial when different layers have very different gradient scales.

```python
optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    betas=(0.9, 0.95),
    weight_decay=0.1
)

# Training loop
for batch_idx, (inputs, targets) in enumerate(dataloader):
    optimizer.zero_grad()
    logits, loss = model(inputs, targets)
    loss.backward()                  # compute all gradients
    
    # Gradient clipping: prevents gradient explosions
    # clips the global L2 norm of all gradients to max_norm
    torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    
    optimizer.step()                 # update weights
```

**Gradient clipping** sets an upper bound on the global L2 norm of the gradient vector. If $\|\mathbf{g}\|_2 > 1.0$, we scale all gradients by $\frac{1.0}{\|\mathbf{g}\|_2}$. This prevents any single bad batch from taking a catastrophically large step.

### Learning Rate Schedule

LLMs use a **cosine decay with warmup**:

$$\text{lr}(t) = \begin{cases} \alpha_{\max} \cdot \frac{t}{T_{warmup}} & t < T_{warmup} \\ \frac{\alpha_{\max}}{2}\left(1 + \cos\left(\pi \cdot \frac{t - T_{warmup}}{T_{total} - T_{warmup}}\right)\right) & t \geq T_{warmup} \end{cases}$$

Warmup prevents large gradient steps at the start when all weights are random. Cosine decay gradually reduces the learning rate to near-zero as training progresses, allowing fine-grained convergence.

## 14. The KV Cache — Why Inference Is Fast

During generation, you generate one token at a time. Without optimization, generating token $T+1$ requires recomputing attention over all $T$ previous tokens from scratch — that's $O(T^2)$ per new token.

The **KV cache** stores the $\mathbf{K}$ and $\mathbf{V}$ matrices from all previous tokens. For each new token:

1. Compute only the new token's $\mathbf{Q}$, $\mathbf{K}$, $\mathbf{V}$
2. Append the new $\mathbf{K}$ and $\mathbf{V}$ to the cache
3. Compute attention scores between the new $\mathbf{Q}$ and the full cached $\mathbf{K}$ matrix

Now each new token costs $O(T)$ instead of $O(T^2)$. The tradeoff is memory: the KV cache grows linearly with sequence length and is proportional to $2 \times n_{layers} \times n_{heads} \times d_k \times T$ values. For a 70B model generating a 100K token sequence, this is tens of gigabytes.

---

## 15. The Context Window — Why It's Limited

The context window $T_{max}$ is a hard architectural constraint for two reasons:

1. **Positional encoding**: Learned position embeddings only cover positions $0$ to $T_{max}-1$. The model has never seen anything beyond that.

2. **Attention complexity**: Full attention is $O(T^2)$ in compute and memory. At $T=128K$, the attention matrix is $128K \times 128K = 16B$ entries. That's ~64GB at float32.

This is why modern research focuses on: **sliding window attention** (attend only to nearby $k$ tokens), **sparse attention**, **linear attention** (approximate softmax to get $O(T)$), and **flash attention** (recompute in tiles that fit in GPU SRAM to avoid memory bottlenecks).

## 16. Generation — Temperature, Sampling, and Decoding

Given logits $\mathbf{z} \in \mathbb{R}^V$, how do you pick the next token?

**Temperature sampling**: Divide logits by temperature $\tau$ before softmax:

$$P_\tau(x) = \frac{\exp(z_x / \tau)}{\sum_{v}\exp(z_v / \tau)}$$

- $\tau \to 0$: argmax (always pick the highest-probability token — deterministic)
- $\tau = 1$: sample from the model's learned distribution
- $\tau > 1$: flatten the distribution, more random output

**Top-k sampling**: After applying temperature, keep only the top-$k$ tokens and renormalize. Prevents the model from sampling very low-probability tokens.

**Top-p (nucleus) sampling**: Keep the smallest set of tokens whose cumulative probability exceeds $p$ (e.g., 0.9). If one token has 95% probability, you just pick it. If the distribution is flat, you consider many tokens.

```python
@torch.no_grad()
def generate(model, idx, max_new_tokens, temperature=1.0, top_k=50):
    for _ in range(max_new_tokens):
        # Crop to context window
        idx_cond = idx[:, -model.max_seq_len:]
        
        logits = model(idx_cond)[:, -1, :]  # (B, V) — last token's logits
        
        # Apply temperature
        logits = logits / temperature
        
        # Top-k: zero out everything except top k
        if top_k is not None:
            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))
            logits[logits < v[:, [-1]]] = float('-inf')
        
        # Sample from distribution
        probs = F.softmax(logits, dim=-1)
        next_token = torch.multinomial(probs, num_samples=1)  # (B, 1)
        
        idx = torch.cat([idx, next_token], dim=1)
    
    return idx
```

## Part 1 — What a Neural Network Actually Is

A neural network is not a separate thing sitting next to the transformer. The transformer *is* made entirely of neural network layers. Every `nn.Linear` is a neural network. Let me show you what that means at the lowest level.

The most primitive neural network unit is a single **neuron**:

$$y = \sigma\left(\sum_{i=1}^{n} w_i x_i + b\right) = \sigma(\mathbf{w}^\top \mathbf{x} + b)$$

It takes an input vector $\mathbf{x}$, multiplies every input by a learned weight $w_i$, sums everything up, adds a bias $b$, then squashes through a nonlinear activation function $\sigma$. That's it. A single neuron is a learned weighted vote.

A **layer** is hundreds or thousands of neurons computed in parallel — which is just matrix multiplication:

$$\mathbf{y} = \sigma(\mathbf{W}\mathbf{x} + \mathbf{b})$$

where $\mathbf{W} \in \mathbb{R}^{d_{out} \times d_{in}}$. Every row of $\mathbf{W}$ is one neuron's weights. The whole FFN, the Q/K/V projections in attention, the final LM head — they are all this same operation, stacked and chained.The weights — those numbers in the matrices — are the entire model. A 7 billion parameter model is literally 7 billion floating point numbers arranged in matrices. Training is the process of finding the right values for all of them.

## Part 2 — Training: What Actually Happens

This is the most misunderstood part. Training is not "showing examples to the model." It is a precise mathematical optimization process. Let me walk through exactly what happens.

### The Setup

You have a massive text corpus — trillions of tokens from the internet, books, code, etc. You have a model with randomly initialized weights $\theta$ (all parameters set to small random numbers). The model currently produces garbage outputs because the weights are random.

Training's goal: find the values of $\theta$ that minimize the average cross-entropy loss across all training examples:

$$\mathcal{L}(\theta) = -\frac{1}{|\mathcal{D}|} \sum_{(x_1,...,x_T) \in \mathcal{D}} \sum_{t=1}^{T-1} \log P_\theta(x_{t+1} \mid x_1,...,x_t)$$

### One Training Step — Exact Process

Take a batch of token sequences. Let's say one sequence: `["The", "cat", "sat", "on", "the", "mat"]` → tokens `[1, 2, 3, 4, 5, 6]`.

**The model sees input** `[1, 2, 3, 4, 5]` and must predict `[2, 3, 4, 5, 6]` at each position simultaneously. This is the critical insight — you get $T-1$ training signals from one sequence, not just one.

**Forward pass** — data flows through every layer, producing logits at every position:
```
position 0 ("The"   → predict "cat"):  logits over 50k vocab
position 1 ("cat"   → predict "sat"):  logits over 50k vocab
position 2 ("sat"   → predict "on"):   logits over 50k vocab
...
```

**Loss computation** — at each position, the correct next token has some logit score. The cross-entropy loss measures how far that score is from being the maximum. If the model assigns 80% probability to the correct token, loss is low. If it assigns 0.001%, loss is high.

**Backward pass** — this is where learning happens. PyTorch computes $\frac{\partial \mathcal{L}}{\partial \theta}$ for every single parameter. The gradient tells you: "if I increase this weight slightly, does the loss go up or down, and by how much?"

The chain rule computes this by working backwards through every operation from loss to inputs. The gradient of the loss with respect to weight $w$ in layer $l$ is:

$$\frac{\partial \mathcal{L}}{\partial w} = \frac{\partial \mathcal{L}}{\partial z^{(L)}} \cdot \frac{\partial z^{(L)}}{\partial z^{(L-1)}} \cdots \frac{\partial z^{(l+1)}}{\partial z^{(l)}} \cdot \frac{\partial z^{(l)}}{\partial w}$$

Each term is a local Jacobian. PyTorch stores these during the forward pass and multiplies them in reverse order during `.backward()`. This is automatic differentiation — you never write gradient code yourself.

**Weight update** — every parameter gets nudged in the direction that reduces loss:

$$\theta \leftarrow \theta - \alpha \cdot \frac{\partial \mathcal{L}}{\partial \theta}$$

(This is the simplest form — SGD. In practice AdamW adapts the step size per parameter as covered in the previous conversation.)

Do this millions of times across trillions of tokens and the weights slowly converge to values that make the model very good at predicting next tokens.

The yellow dot is the current weight configuration. The green arrow is the negative gradient — the direction of steepest descent. Hit "Auto" and watch it find the minimum.

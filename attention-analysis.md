### 2. DeepSeek V3.2 — The Previous Generation (December 2025)

For completeness, since V3.2 is still widely discussed:

The only architectural modification in DeepSeek-V3.2 compared to V3.1-Terminus was the introduction of **DeepSeek Sparse Attention (DSA)** through continued training. DSA consists of two components: a **lightning indexer** and a **fine-grained token selection mechanism**. DSA was instantiated under MLA for this release.

DSA reduces computational complexity from quadratic O(L²) to linear O(Lk), where k ≪ L is the number of selected tokens. So V3.2 was **MLA + DSA hybrid** — V4 is a full redesign on top of that.

### 4. The Muon Optimizer — What It Is and Why It Matters

Both Kimi K2 and now DeepSeek V4 use Muon. Here's what it actually does:

**Muon (MomentUm Orthogonalized by Newton-Schulz)** optimizes 2D neural network parameters by taking the updates generated by SGD-momentum and applying a **Newton-Schulz iteration** as a post-processing step to each of them before applying to the parameters. The function of the NS iteration is to approximately *orthogonalize* the update matrix — to replace SGD-momentum's update with the nearest semi-orthogonal matrix to it. This is equivalent to replacing the update by UV^T, where USV^T is its singular value decomposition.

**Why orthogonalize?** Updates produced by both SGD-momentum and Adam for 2D parameters in transformer networks typically have very high condition number — they are almost low-rank matrices, with updates for all neurons dominated by just a few directions. Orthogonalization effectively increases the scale of other "rare directions" which have small magnitude but are nevertheless important for learning.

**The efficiency trick:** SVD is too slow for real use. Instead, Newton-Schulz iterations can be stably run in **bfloat16**, making them fast on modern GPUs. The **FLOP overhead of Muon is at most Tm/B** (where m is the model dimension, B is the batch size in tokens, T is the number of NS steps). For typical LM training scenarios at both small and large scale, Muon has a FLOP overhead below **1%**.

**Relationship to Shampoo:** If preconditioner accumulation is removed from Shampoo, the update becomes the orthogonalized gradient (UV^T). Adding momentum before the orthogonalization recovers the Muon update — but with lower wallclock overhead due to Newton-Schulz iteration instead of inverse-fourth roots. Muon can be interpreted as a kind of "instantaneous" or "accumulation-free" Shampoo.

When using Muon: scalar, vector, and input/output embedding parameters still use AdamW. Muon only replaces the optimizer for the 2D hidden weight matrices.

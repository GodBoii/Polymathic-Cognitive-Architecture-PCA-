The Core Problem — What Are We Solving?

Before a single weight is trained, we must frame the problem precisely. An LLM is an autoregressive language model. Given tokens seen so far, predict the probability of what comes next.

Chain Rule of Probability — The Fundamental Objective
\[ P(x_1, x_2, \ldots, x_T) = \prod_{t=1}^{T} P(x_t \mid x_1, \ldots, x_{t-1}) \]
SymbolMeaningWhy it's here
P(x₁,…,xᵀ)Joint probability of an entire sequence of T tokensThis is the thing the model is ultimately learning — how probable is this sequence of words?
∏ (product)Multiply all terms togetherJoint probability of independent conditionals is their product
xₜThe token at position tThe single token we're predicting at each step
x₁,…,xₜ₋₁All previous tokensEverything the model has seen so far — the "context"
TTotal sequence lengthHow many tokens are in this sequence

This is the chain rule of probability applied to language. You can always factor any joint probability this way — it's mathematically exact. The model's entire job is to learn each P(xₜ | x<ₜ) accurately.

Training Objective — Cross-Entropy Loss (Minimize This)
\[ \mathcal{L} = -\frac{1}{T}\sum_{t=1}^{T} \log P_\theta(x_t \mid x_{<t}) \]
SymbolMeaningEffect on Training
𝓛Loss — a single scalar number measuring how wrong the model isWe want this as small as possible (ideally 0)
−Negative signlog of a probability is always negative; we flip it so higher probability = lower loss
1/TAverage over all token positionsNormalizes so loss doesn't scale with sequence length
∑Sum over all positions t from 1 to TWe get one training signal per token — T signals from one sequence
logNatural logarithmConverts probabilities (0 to 1) to log-likelihoods (−∞ to 0). log(0.9) ≈ −0.1, log(0.001) = −6.9
P_θThe model's predicted probability, given parameters θθ (theta) means "all weights in the model" — billions of floating point numbers
x_tThe actual correct next tokenThe ground truth from the training data
x<tAll tokens before position tThe context the model gets to "see" before predicting
Intuition

If the model assigns 90% probability to the correct token: loss = −log(0.9) ≈ 0.10. If it assigns 0.1% probability: loss = −log(0.001) = 6.9. Training pushes the model to always assign high probability to correct tokens by adjusting every weight.

Token Embeddings — Integers to Geometry

Tokens are integers. You cannot do meaningful math on integers — integer 42 has no more "meaning" than integer 891. The solution: map every token to a high-dimensional real vector where distance and direction encode meaning.

Embedding Lookup
\[ \mathbf{e}_i = \mathbf{E}[x_i] \in \mathbb{R}^d \]
SymbolMeaningConcrete example
EEmbedding matrix of shape (V × d)For GPT-2: shape (50257, 768) — 50,257 tokens, each a 768-dim vector
VVocabulary size50,257 for GPT-2; 128,000 for modern models
dEmbedding dimension768 for GPT-2, 4096 for LLaMA-7B
xᵢToken index (an integer)Token "hello" might be integer 9906
eᵢThe embedding vector for token iA list of 768 floating-point numbers
E[xᵢ]Row lookup — take row xᵢ from matrix EThis is literally just array indexing. No math — just a lookup.
ℝᵈ"A real vector of d dimensions"768 numbers that can be any real value
Why This Works

During training, backpropagation updates these rows. The model learns that "king" and "queen" appear in similar contexts, so their embedding vectors converge to similar directions. A famous result emerges: king − man + woman ≈ queen. The 768 dimensions become abstract axes of meaning — gender, royalty, age, etc.

Positional Encoding — Teaching the Model About Order

Self-attention (next section) is completely position-agnostic by default. Shuffle your tokens and you get the same output. We must inject position information so "dog bites man" ≠ "man bites dog".

Sinusoidal Positional Encoding (Original Transformer — Vaswani et al. 2017)
\[ PE_{(pos,\, 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d}}\right) \qquad PE_{(pos,\, 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d}}\right) \]
SymbolMeaningWhy this value
posPosition index (0, 1, 2, … T−1)Which position in the sequence is this token at?
iDimension index (0 to d/2−1)Which pair of dimensions in the encoding vector
dEmbedding dimension (e.g. 768)Must match embedding dimension so they can be added
10000Base frequency constantCreates frequencies ranging from 1 cycle/position to 1 cycle/10000 positions. Chosen so different dimensions encode different "scales" of position.
2i / dExponent that varies the frequency per dimensionLow i = high frequency (fine-grained position); high i = low frequency (coarse position)
sin/cos alternationEven dims get sin, odd dims get cosAllows PE(pos+k) to be written as a linear function of PE(pos), making it easy for attention to compute relative offsets
\[ \mathbf{h}_i = \mathbf{e}_i + PE_i \]

The final input to the transformer is the token embedding plus the position encoding — element-wise addition.

RoPE — Rotary Position Embeddings (LLaMA, Modern Models)
\[ \mathbf{q}_m^{(2i:2i+2)} = \begin{pmatrix} \cos(m\theta_i) & -\sin(m\theta_i) \\ \sin(m\theta_i) & \cos(m\theta_i) \end{pmatrix} \mathbf{q}^{(2i:2i+2)}, \qquad \theta_i = 10000^{-2i/d} \]
SymbolMeaningKey insight
mAbsolute position of the query tokenThe token we're computing attention for
θᵢRotation angle per dimension pair iEach pair of dimensions rotates at a different speed
2×2 matrix2D rotation matrixRotates a 2D slice of the query vector by angle m·θᵢ
q^(2i:2i+2)A 2D slice (pair) of the query vectorRoPE operates on consecutive dimension pairs
Why Rotate Instead of Add?

When you compute the dot product q_m · k_n, the rotation matrices cancel out and the result depends only on the relative position (m − n), not absolute positions. This gives the model natural relative position awareness and generalizes better to longer sequences than learned absolute positions.

Self-Attention — The Core Mechanism

This is the heart of the transformer. For every token, it asks: "which other tokens are relevant to understanding me?" Then it gathers information from those tokens proportionally to their relevance.

Step 1 — Project to Queries, Keys, Values

QKV Projections
\[ \mathbf{q}_i = \mathbf{h}_i \mathbf{W}_Q, \quad \mathbf{k}_i = \mathbf{h}_i \mathbf{W}_K, \quad \mathbf{v}_i = \mathbf{h}_i \mathbf{W}_V \]
SymbolMeaningDatabase analogy
hᵢThe current representation of token i (shape: d)The token's current "state"
W_Q ∈ ℝ^(d×d_k)Query projection weight matrix — learnedTransforms token to "what I'm looking for"
W_K ∈ ℝ^(d×d_k)Key projection weight matrix — learnedTransforms token to "what label I advertise"
W_V ∈ ℝ^(d×d_k)Value projection weight matrix — learnedTransforms token to "what information I carry"
qᵢQuery vector for token i (shape: d_k)The search query token i fires
kᵢKey vector for token i (shape: d_k)The "index card" label of token i
vᵢValue vector for token i (shape: d_k)The actual content to read if you attend to i
d_kHead dimension = d / n_headsFor GPT-2: 768 / 12 = 64 per head

Step 2 — The Full Attention Formula

Scaled Dot-Product Attention — The Most Important Formula in LLMs
\[ \text{Attention}(\mathbf{Q}, \mathbf{K}, \mathbf{V}) = \text{softmax}\!\left(\frac{\mathbf{Q}\mathbf{K}^\top}{\sqrt{d_k}}\right)\mathbf{V} \]
SymbolShapeMeaning
Q(T × d_k)All query vectors stacked — one row per token
K(T × d_k)All key vectors stacked — one row per token
V(T × d_k)All value vectors stacked — one row per token
QK^T(T × T)Every query dot-producted with every key. Entry (i,j) = how relevant is token j to token i
√d_kscalarScaling factor. Prevents dot products from getting too large when d_k is big
softmax(…)(T × T)Converts raw scores to a probability distribution. Each row sums to 1.
…V(T × d_k)Weighted sum: each token's output is a mixture of all value vectors, weighted by attention

Why divide by √d_k?

If q and k have components with mean 0 and variance 1, then their dot product q·k = Σᵢ qᵢkᵢ has variance d_k (sum of d_k independent unit-variance terms). Standard deviation = √d_k. So we divide by √d_k to bring variance back to 1.

\[ \text{Var}\!\left[\sum_{i=1}^{d_k} q_i k_i\right] = \sum_{i=1}^{d_k} \text{Var}[q_i k_i] = d_k \implies \text{Std}[q \cdot k] = \sqrt{d_k} \]

Without this: large d_k → huge dot products → softmax outputs near 0 or 1 → gradients ≈ 0 → model doesn't learn.

Causal Mask (Decoder-Only / GPT-Style)
\[ \text{mask}_{ij} = \begin{cases} 0 & \text{if } j \leq i \\ -\infty & \text{if } j > i \end{cases} \]
SymbolMeaningEffect
iQuery token position (the token computing attention)The "current" token
jKey token position (being attended to)The "past" token being looked at
j ≤ i → 0Token can attend to itself and earlier tokensNormal attention score used
j > i → −∞Token CANNOT attend to future tokensAfter softmax: exp(−∞) = 0 → zero attention weight. Future is invisible.
Why Do We Need This?

During training, we process all T tokens simultaneously for efficiency. But the model must only predict the next token based on what came before — not from tokens that haven't been generated yet. The mask enforces this causality constraint mathematically.

Multi-Head Attention — Parallel Attention

One attention head captures one type of relationship between tokens. Language needs many simultaneously: syntactic roles, coreference, semantic similarity, positional proximity. Multi-head attention runs h heads in parallel, each learning different relationships.

Multi-Head Attention Formula
\[ \text{MultiHead}(\mathbf{H}) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\,\mathbf{W}_O \] \[ \text{where} \quad \text{head}_i = \text{Attention}(\mathbf{H}\mathbf{W}_Q^{(i)},\, \mathbf{H}\mathbf{W}_K^{(i)},\, \mathbf{H}\mathbf{W}_V^{(i)}) \]
SymbolMeaningDetail
hNumber of attention headsGPT-2 small: 12 heads; GPT-4: estimated 128 heads
head_iOutput of the i-th attention headShape: (T × d_k) where d_k = d/h
W_Q^(i), W_K^(i), W_V^(i)Separate projection matrices per headEach head learns to look for different things
Concat(…)Concatenate all heads along feature dimensionh heads × d_k each = d total. No information loss.
W_O ∈ ℝ^(d×d)Output projection matrixMixes information across heads — lets model learn which head combinations matter
d_k = d / hPer-head dimensionTotal parameters unchanged vs single head: same compute, richer representations
What Each Head Learns

Research shows different heads specialize: head 1 might track which noun a pronoun refers to ("it" → "animal"), head 2 might track verb-subject agreement, head 3 might track adjacent tokens. No head is programmed to do this — they specialize through training because it reduces the loss.

The Residual Stream — Why Skip Connections Are Critical

Residual Connection
\[ \mathbf{x}' = \mathbf{x} + \text{Sublayer}(\mathbf{x}) \]
SymbolMeaning
xInput to this block (the "residual stream" carrying all previous information)
Sublayer(x)The output of attention or FFN — the "delta" to add
x'Output: original x plus the correction

Gradient Flow — Why This Solves Vanishing Gradients

\[ \frac{\partial \mathcal{L}}{\partial \mathbf{x}} = \frac{\partial \mathcal{L}}{\partial \mathbf{x}'}\!\underbrace{\left(1 + \frac{\partial \,\text{Sublayer}(\mathbf{x})}{\partial \mathbf{x}}\right)}_{\text{always} \geq 1 \text{ due to the `1'}} \]
SymbolMeaningCritical role
∂𝓛/∂xGradient of loss w.r.t. this layer's inputHow much this layer's input contributed to the error
∂𝓛/∂x'Gradient flowing from the next layerThe gradient coming back from deeper layers
The "1" termDirect gradient path through the residualGuarantees gradients always have a highway to travel back — cannot vanish to zero even with 100+ layers
∂Sublayer/∂xGradient through the sublayer itselfThis can still vanish, but the "1" saves us
Mental Model

Think of a highway running through the entire network. The residual stream IS that highway. Attention and FFN are on-ramps that add information. The original token identity is always present — each layer only needs to learn what small "correction" to add, not the entire representation. This makes 96-layer models trainable.

Layer Normalization — Keeping Activations Stable

Layer Norm Formula
\[ \text{LayerNorm}(\mathbf{x}) = \gamma \odot \frac{\mathbf{x} - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta \]

Statistics

\[ \mu = \frac{1}{d}\sum_{j=1}^{d} x_j \]

Mean across feature dimension d

\[ \sigma^2 = \frac{1}{d}\sum_{j=1}^{d}(x_j - \mu)^2 \]

Variance across feature dimension d

Learned Parameters

γ (gamma) ∈ ℝᵈ — learned scale, init to 1.0. Lets the model re-scale after normalization.

β (beta) ∈ ℝᵈ — learned shift, init to 0. Lets the model re-center after normalization.

ε ≈ 10⁻⁵ — tiny constant to prevent division by zero when σ² = 0

SymbolMeaningWhy needed
x − μSubtract mean — zero-center the vectorRemoves bias in activation magnitudes
/ √(σ²+ε)Divide by std — normalize to unit varianceDifferent layers can produce wildly different activation scales; this standardizes them
⊙ (hadamard)Element-wise multiplication by γRestore the scale the model needs — pure normalization can be too restrictive
+ βAdd learned biasRestore the offset the model needs
Why Not Batch Norm?

Batch Norm normalizes across the batch dimension — it needs statistics from many samples simultaneously. During autoregressive generation, you process one token at a time (batch size 1). Layer Norm normalizes across the feature dimension independently per token, so it works at batch size 1. This is why transformers use Layer Norm.

Feed-Forward Network — The Model's Memory Store

After attention gathers information across tokens, every token's representation passes through an FFN independently (same FFN per position, different inputs). This is where factual knowledge is stored.

Standard FFN (GPT-2 Style)
\[ \text{FFN}(\mathbf{x}) = \mathbf{W}_2 \cdot \text{GELU}\!\left(\mathbf{W}_1 \mathbf{x} + \mathbf{b}_1\right) + \mathbf{b}_2 \]
SymbolShapeMeaning
W₁(d × 4d)First linear projection — expands dimension 4×. Rows are "key patterns"
W₂(4d × d)Second linear projection — compresses back to d. Columns are "values"
b₁, b₂bias vectorsLearned offsets for each neuron
4dhidden dimensionThe 4× expansion is empirical — from the original Transformer paper. Gives the FFN a large "working memory"
GELUactivation functionNonlinearity — without this, any number of linear layers collapses to a single linear layer (useless)
GELU Activation Function
\[ \text{GELU}(x) = x \cdot \Phi(x) = x \cdot \frac{1}{2}\!\left[1 + \text{erf}\!\left(\frac{x}{\sqrt{2}}\right)\right] \]
SymbolMeaningBehavior
xInput scalar (a single neuron's pre-activation value)Can be any real number
Φ(x)Standard normal CDF (cumulative distribution function)Ranges from 0 to 1; = 0.5 at x=0
erfError functionRelated to the area under a Gaussian curve
x · Φ(x)Soft gatingLarge positive x: GELU(x) ≈ x (passes through). Large negative x: GELU(x) ≈ 0 (blocked). Near zero: probabilistically gated.
GELU vs ReLU

ReLU: max(0, x) — hard cut at 0. GELU: smooth, differentiable everywhere. Small negative values aren't completely zeroed. This smoothness helps gradients flow better during training, which is why GPT-2 and all modern models use GELU or variants.

SwiGLU (LLaMA / Modern Models)
\[ \text{SwiGLU}(\mathbf{x}) = \mathbf{W}_2\,\bigl(\text{SiLU}(\mathbf{W}_1\mathbf{x}) \odot \mathbf{W}_3\mathbf{x}\bigr) \] \[ \text{SiLU}(x) = x \cdot \sigma(x) = \frac{x}{1 + e^{-x}} \]
SymbolMeaning
W₁xThe "activated" branch — passed through SiLU nonlinearity
W₃xThe "gate" branch — linear, used to multiplicatively gate the activated branch
⊙Element-wise multiplication — the gate controls how much of each neuron's activation passes through
σ(x)Sigmoid function — squashes x to (0, 1)

SwiGLU adds a multiplicative gate: the network learns to suppress certain dimensions by setting the gate near zero. This gives extra expressivity at the same parameter count and has been shown to empirically outperform standard GELU FFNs.

Neurons & How Weights Are Created

The transformer is entirely made of neural network layers. "Neural networks" are not a separate component — they are the attention projections, FFN layers, and LM head. Here's the lowest level.

Single Neuron — The Atomic Unit
\[ y = \sigma\!\left(\sum_{i=1}^{n} w_i x_i + b\right) = \sigma(\mathbf{w}^\top \mathbf{x} + b) \]
SymbolMeaningConcrete example
xᵢThe i-th input valueOne dimension of a token's embedding vector
wᵢThe learned weight for input iA floating point number, e.g. 0.247. Updated during training.
bBias termA single number allowing the neuron to shift its activation threshold
Σ wᵢxᵢWeighted dot product — the "vote count"Large positive = strong signal; large negative = strong negative signal
σActivation function (GELU, SiLU, or similar)Introduces nonlinearity — without it, any depth of network = one linear transformation
yThe neuron's outputOne number; feeds into the next layer
A Layer — Many Neurons in Parallel (Matrix Form)
\[ \mathbf{y} = \sigma(\mathbf{W}\mathbf{x} + \mathbf{b}) \quad \text{where } \mathbf{W} \in \mathbb{R}^{d_{\text{out}} \times d_{\text{in}}} \]
SymbolMeaning
WWeight matrix. Each ROW is one neuron's weights. The layer is ALL neurons at once.
d_inInput dimension — how many features come in
d_outOutput dimension — how many neurons are in this layer
WxMatrix-vector multiply — computes all neurons' dot products simultaneously (parallelized on GPU)
+ bBias vector — one bias per output neuron
How Weights Are Created Initially

Weights start random — drawn from a small normal distribution (e.g. N(0, 0.02)). They're meaningless at first. The entire model is random noise at step 0. Training via backpropagation slowly adjusts these numbers over millions of steps until they encode language knowledge. A 7B parameter model is just 7 billion floating-point numbers in matrices — the "knowledge" is the specific values those numbers converge to.

Cross-Entropy Loss — Measuring the Model's Error

Training Loss — Full Dataset Version
\[ \mathcal{L}(\theta) = -\frac{1}{|\mathcal{D}|} \sum_{(x_1,\ldots,x_T)\in \mathcal{D}} \sum_{t=1}^{T-1} \log P_\theta(x_{t+1} \mid x_1,\ldots,x_t) \]
SymbolMeaningScale
𝒟Training dataset — all sequencesTrillions of tokens from the internet, books, code
|𝒟|Size of training setNormalizes loss so it doesn't grow with data size
Σ sequencesSum over all training sequencesEvery document, every code file
Σ t from 1 to T−1Sum over all positions in sequenceOne prediction per token = T−1 training signals per sequence. Very efficient!
log P_θ(x_{t+1} | …)Log probability of the actual next tokenlog(0.9) ≈ −0.1 (good), log(0.001) = −6.9 (bad)
Cross-Entropy — The Numerically Stable Form
\[ \mathcal{L}_{CE} = -\log\frac{\exp(\text{logit}_{x^*})}{\sum_{v'}\exp(\text{logit}_{v'})} = \underbrace{\log\sum_{v'}\exp(\text{logit}_{v'})}_{\text{log-sum-exp}} - \text{logit}_{x^*} \]
SymbolMeaning
logit_vRaw score for token v from the LM head (before softmax)
x*The correct next token (ground truth from data)
log Σ exp(…)Log-sum-exp: computed as max(logits) + log Σ exp(logit − max). This prevents overflow when logits are large.
− logit_{x*}Subtract the correct token's logit. High logit = negative contribution to loss = lower loss.

Backpropagation — How the Model Learns

Backpropagation computes the gradient of the loss with respect to every single parameter. This tells us: "if I increase weight W slightly, does the loss go up or down, and by how much?" We then nudge every weight in the direction that reduces loss.

Chain Rule — The Engine of Backpropagation
\[ \frac{\partial \mathcal{L}}{\partial w} = \frac{\partial \mathcal{L}}{\partial z^{(L)}} \cdot \frac{\partial z^{(L)}}{\partial z^{(L-1)}} \cdots \frac{\partial z^{(l+1)}}{\partial z^{(l)}} \cdot \frac{\partial z^{(l)}}{\partial w} \]
SymbolMeaning
∂𝓛/∂wGradient of loss w.r.t. weight w — this is what we need
z^(l)Activations at layer l (the output of that layer)
∂z^(l+1)/∂z^(l)Local Jacobian — how layer l's output affects layer l+1's output
∂z^(l)/∂wHow weight w affects layer l's output
The chainMultiply local Jacobians from output back to the layer containing w. PyTorch does this automatically via autograd.
What PyTorch Does

During the forward pass, PyTorch builds a computation graph — a record of every operation. During loss.backward(), it traverses this graph in reverse, computing gradients layer by layer using the chain rule. You never write gradient code yourself — autograd handles it all.

Gradient Descent — Weight Update Rule (SGD)
\[ \theta \leftarrow \theta - \alpha \cdot \frac{\partial \mathcal{L}}{\partial \theta} \]
SymbolMeaning
θA weight (or all weights vectorized). Could be any of the billions of parameters.
←Assignment. Theta is updated in-place.
α (alpha)Learning rate — how big a step to take. Too large: overshoots. Too small: too slow. Typical: 1e-4 to 3e-4.
∂𝓛/∂θGradient of loss w.r.t. θ. Positive = increasing θ increases loss. We subtract it (go downhill).
−α·gradientMove θ in the opposite direction of the gradient — toward lower loss (gradient descent)

AdamW Optimizer — Adaptive Learning Rates

Plain SGD uses one learning rate for all parameters. AdamW adapts the learning rate per parameter based on the history of its gradients. Parameters with consistently large gradients get smaller steps; parameters with small gradients get larger steps.

AdamW — Full Update Rule (4 Equations)
\[ \mathbf{g}_t = \frac{\partial \mathcal{L}}{\partial \theta_t} \quad \text{(gradient at step t)} \] \[ \mathbf{m}_t = \beta_1 \mathbf{m}_{t-1} + (1-\beta_1)\mathbf{g}_t \quad \text{(1st moment — momentum)} \] \[ \mathbf{v}_t = \beta_2 \mathbf{v}_{t-1} + (1-\beta_2)\mathbf{g}_t^2 \quad \text{(2nd moment — squared gradient)} \] \[ \hat{\mathbf{m}}_t = \frac{\mathbf{m}_t}{1-\beta_1^t}, \quad \hat{\mathbf{v}}_t = \frac{\mathbf{v}_t}{1-\beta_2^t} \quad \text{(bias correction)} \] \[ \theta_t = \theta_{t-1} - \alpha \frac{\hat{\mathbf{m}}_t}{\sqrt{\hat{\mathbf{v}}_t} + \epsilon} - \underbrace{\lambda\alpha\theta_{t-1}}_{\text{weight decay}} \]
SymbolMeaningValue/Effect
gₜGradient at step tRaw gradient from backpropagation
mₜFirst moment (exponential moving average of gradient)Like momentum in physics — smooths out noise. β₁ = 0.9 means "90% of last step's momentum"
vₜSecond moment (EMA of gradient squared)Estimates the typical gradient magnitude. β₂ = 0.95 typically
β₁ = 0.9Momentum decay for 1st moment90% of previous momentum, 10% new gradient
β₂ = 0.95Momentum decay for 2nd moment95% of previous, 5% new
m̂ₜ, v̂ₜBias-corrected momentsAt step 1, m₁ = (1−β₁)·g₁ which underestimates. Dividing by (1−β₁ᵗ) corrects this.
α / (√v̂ + ε)Adaptive effective learning rateIf gradient has been large (v̂ big): small step. If gradient has been small (v̂ small): larger step. Automatic per-parameter tuning.
ε = 10⁻⁸Numerical stabilityPrevents division by zero when v̂ is tiny
λα θₜ₋₁Weight decay (the "W" in AdamW)λ = 0.1 typically. Directly penalizes large weights — regularization. Decoupled from the adaptive LR unlike standard Adam.
Why AdamW Over Plain SGD?

Different parameters in the model have vastly different gradient scales. Embedding gradients are sparse and small; attention weight gradients can be large. A single learning rate for all of them is suboptimal. AdamW's adaptive scaling means each parameter effectively gets its own tuned learning rate, making training much more stable and efficient across all parameters simultaneously.

Learning Rate Schedule — Warmup + Cosine Decay

Cosine Decay with Linear Warmup
\[ \text{lr}(t) = \begin{cases} \alpha_{\max} \cdot \dfrac{t}{T_{\text{warmup}}} & t < T_{\text{warmup}} \\[10pt] \dfrac{\alpha_{\max}}{2}\!\left(1 + \cos\!\left(\pi \cdot \dfrac{t - T_{\text{warmup}}}{T_{\text{total}} - T_{\text{warmup}}}\right)\right) & t \geq T_{\text{warmup}} \end{cases} \]
SymbolMeaningWhy
α_maxPeak learning rate (e.g. 3e-4)The maximum step size the optimizer will ever take
T_warmupNumber of warmup steps (e.g. 2000)Gradual ramp-up period
T_totalTotal training stepsEnd of training
Warmup phase (t < T_warmup)LR linearly increases from 0 to α_maxAt step 0, all weights are random. Large gradients + large LR = chaotic first steps. Warmup lets the model stabilize before taking big steps.
Cosine phase (t ≥ T_warmup)LR follows cosine curve from α_max to ≈0Gradual decay: quick progress early, fine-grained refinement later. Cosine is smooth — no sudden drops.
cos(π·…) / 2 + 0.5Cosine from 1 to −1, scaled to 1 to 0At t=T_warmup: cos(0) = 1 → lr = α_max. At t=T_total: cos(π) = −1 → lr ≈ 0

LM Head & Softmax — From Vectors to Probabilities

Language Modeling Head + Weight Tying
\[ \text{logits} = \mathbf{h}_T \,\mathbf{W}_{\text{emb}}^\top \in \mathbb{R}^V \]
SymbolMeaningWhy
h_TFinal hidden state of the last token (shape: d)The model's compressed representation of the entire context
W_emb^TTranspose of the token embedding matrixWeight tying: same matrix used for both input embeddings and output prediction. If two tokens have similar embeddings, they should be predicted with similar probability in similar contexts. Saves ~38M parameters for GPT-2.
logits ∈ ℝᵛRaw scores for every vocabulary tokenV values (e.g. 50,257). High score = model thinks this is the next token.
Softmax — Converting Logits to Probabilities
\[ P(x_{T+1} = v \mid x_{\leq T}) = \frac{\exp(\text{logit}_v)}{\sum_{v'=1}^{V} \exp(\text{logit}_{v'})} \]
SymbolMeaning
exp(logit_v)Exponentiate the score for token v — maps any real number to a positive number
Σ exp(logit_v')Sum over ALL V tokens — normalization denominator. Ensures outputs sum to 1.0 (a valid probability distribution)
ResultA probability distribution over V tokens. The model's "belief" about what comes next.

Temperature & Sampling — Controlling Randomness

Temperature Sampling
\[ P_\tau(x) = \frac{\exp(z_x / \tau)}{\sum_{v}\exp(z_v / \tau)} \]
SymbolMeaningEffect
z_xLogit (raw score) for token xHigher = model thinks x is more likely
τ (tau)Temperature — the single control knob for randomnessDivides all logits before softmax
τ → 0Temperature near zeroArgmax — always pick the highest probability token. Deterministic but repetitive.
τ = 1Temperature = 1 (default)Sample from the model's learned distribution as-is
τ > 1Temperature above 1Divide logits by >1 → flatten distribution → more uniform → more random output
τ < 1Temperature below 1Divide logits by <1 = multiply → sharpen distribution → more confident → more deterministic
Why "Temperature"?

From statistical mechanics: in thermodynamics, temperature controls the "spread" of a system's energy distribution. High temperature = spread out (random). Low temperature = concentrated (ordered). The analogy is exact mathematically — this is the Boltzmann distribution.

Top-K Sampling

Keep only the top K tokens, zero out the rest, renormalize. Prevents sampling from very low-probability tokens that would produce nonsense. Typical k = 40–50.

Top-P (Nucleus) Sampling

Keep the smallest set of tokens whose cumulative probability exceeds p (e.g. 0.9). If one token has 95% probability: just pick it. If flat: consider many tokens. Adapts dynamically.

KV Cache — Why Inference Is Fast

During generation, naively recomputing attention over all T previous tokens for every new token costs O(T²) per step. The KV cache eliminates redundant computation.

Attention Complexity — Without vs With KV Cache
\[ \text{Without cache: } O(T^2 \cdot d) \text{ per new token} \] \[ \text{With KV cache: } O(T \cdot d) \text{ per new token} \]
FactorWithout CacheWith KV Cache
Recompute Q, K, VYes — all T tokens recomputedNo — only the new token's Q, K, V are computed
Attention matrix(T × T) full recomputeNew Q (1 × d_k) dot all cached K (T × d_k) → (1 × T) only
Memory costNone (compute-only)2 × n_layers × n_heads × d_k × T values stored. For 70B model at 100K tokens: tens of GB.
SpeedQuadratic slowdown as sequence growsLinear — each new token takes constant extra time
What's Cached

Once a token's K and V vectors are computed, they never change (they only depend on that token's position and the weights, which are fixed at inference time). So we compute them once and reuse them for every subsequent token generation step.

Full Data Flow — From Text to Token Prediction

Every step of the complete pipeline, with the equation that governs it:

Step 1 — Tokenize

"Hello world" → [9906, 1917]. Integers only.

Step 2 — Embed + Position

\( \mathbf{x} = \mathbf{E}[\text{idx}] + \mathbf{P}[\text{pos}] \in \mathbb{R}^{T \times d} \)

Step 3 — N × Transformer Block (repeated N times)

Pre-norm: \(\hat{\mathbf{x}} = \text{LN}(\mathbf{x})\)
Attention: \(\mathbf{x} \leftarrow \mathbf{x} + \text{softmax}(\hat{\mathbf{Q}}\hat{\mathbf{K}}^\top/\sqrt{d_k})\hat{\mathbf{V}}\mathbf{W}_O\)
Pre-norm 2: \(\hat{\mathbf{x}} = \text{LN}(\mathbf{x})\)
FFN: \(\mathbf{x} \leftarrow \mathbf{x} + \mathbf{W}_2\,\text{GELU}(\mathbf{W}_1\hat{\mathbf{x}})\)

Step 4 — Final LN + LM Head

\( \text{logits} = \text{LN}(\mathbf{x})\,\mathbf{W}_{\text{emb}}^\top \in \mathbb{R}^{T \times V} \)

Step 5 — Training: Minimize Loss

\( \mathcal{L} = -\frac{1}{T}\sum_t \log P_\theta(x_{t+1} \mid x_{\leq t}) \) using AdamW optimizer

Step 6 — Generation: Autoregressive Sampling

\( P_\tau(x) = \frac{\exp(z_x/\tau)}{\sum_v \exp(z_v/\tau)} \) with top-k/top-p filtering, KV cache for speed

The Unified Picture

Every architectural choice has a mathematical justification: scaling by √d_k prevents softmax saturation; residuals solve vanishing gradients; Layer Norm stabilizes activations across layers; weight tying exploits the geometric structure of the embedding space; temperature controls the entropy of predictions; KV caching trades memory for speed. None of these were arbitrary choices — each was discovered by understanding what the math requires.
